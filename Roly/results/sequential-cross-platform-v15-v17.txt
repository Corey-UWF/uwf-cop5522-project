COP 5522 Project 1
Cross-Platform Sequential Performance Record
==============================================

Scope
-----
This record consolidates the verified file-driven sequential
experiments performed on:

    1. cs-ssh
    2. SDSC Expanse

The Linux VM was used for development and validation, but its
performance measurements are not treated as official target-system
results in this comparison.

All three implementations use the professor-compatible four-file
interface and the same frozen benchmark input files.

Workload
--------
N = 4000
F = 128
H = 64

nnz per row = 16
nnz(A) = 64000

The sparse matrix is deterministic and regular, with exactly
16 nonzeros per row.

This workload is NOT a power-law or otherwise irregular sparse
graph. Conclusions about scheduling or load balance must therefore
not be generalized to irregular graph workloads.

Implementations
---------------
v15:
    Professor-style portable baseline
    Association: (A X) W

v16:
    Optimized sparse and dense kernels
    Association: (A X) W
    Sparse feature blocking: 128
    Software prefetch: disabled
    Dense multiply traversal: i-k-j

v17:
    Same optimized kernels as v16
    Association changed to: A (X W)

Nominal Floating-Point Operations
---------------------------------
v15 / v16:
    81,920,000 FLOPs

v17:
    73,728,000 FLOPs

For F = 128 and H = 64, v17 performs 10.00% fewer nominal
floating-point operations than v16.

Because v16 and v17 have different operation counts, runtime is the
primary metric when comparing the two algorithms.

Measurement Methodology
-----------------------
For both target systems:

    - Same frozen C sources
    - Same frozen input files
    - GCC 8.5.0
    - Compiler flags:
          -Wall -pedantic -std=c99 -O3
    - File I/O excluded from timed region
    - One warm-up per implementation
    - Five measured runs
    - Execution order rotated among v15, v16, and v17
    - Median of five measured runs used as primary result
    - Correctness verified independently of performance conclusions

CROSS-PLATFORM COMPARISON
================================================================

Median Runtime
--------------
                         cs-ssh        Expanse
v15 baseline             32.369 ms     32.284 ms
v16 optimized (AX)W       7.886 ms      7.226 ms
v17 optimized A(XW)       5.187 ms      5.745 ms

Observed Cross-System Behavior
------------------------------
v15:
    Baseline performance is very similar across the two systems.
    Expanse's median runtime is approximately 0.26% lower.

v16:
    Expanse is approximately 1.091x faster than cs-ssh.
    Its median runtime is approximately 8.36% lower.

v17:
    cs-ssh is approximately 1.107x faster than Expanse.
    Its median runtime is approximately 9.70% lower.

Therefore, neither architecture is uniformly faster for every
implementation.

Reassociation
-------------
Changing from:

    (A X) W

to:

    A (X W)

improved runtime on BOTH target systems for this matrix shape.

cs-ssh:
    v17 / v16 speedup = 1.520x
    runtime reduction = 34.22%

Expanse:
    v17 / v16 speedup = 1.258x
    runtime reduction = 20.51%

The optimization therefore transfers across architectures, but the
magnitude of the benefit is architecture-dependent.

The 10.00% reduction in nominal FLOPs does not by itself explain the
full measured runtime reduction. Additional effects may include
memory-access behavior, locality, vectorization behavior, and the
smaller intermediate matrix in A(XW), but those mechanisms should
not be claimed as the cause without profiling evidence.

-----------

Verified v15/v16 output SHA-256:
    8e708a154ae67ca79a153c388526aa1d34e5b08abed998c3a1d87361bf16da29

v17 changes floating-point evaluation order because the matrix
multiplications are reassociated.

    Elements checked: 256000
    Maximum absolute difference: 6.11e-05
    Maximum relative difference: 7.49260208e-07
    Tolerance failures: 0

Tolerance:
    absolute = 1e-4
    relative = 1e-4

The same numerical agreement was observed on both target systems.

Current Sequential Conclusion
-----------------------------
For the tested N=4000, F=128, H=64 regular workload, v17 A(XW) is
the fastest sequential implementation tested on both cs-ssh and
Expanse.

This is NOT evidence that A(XW) is universally preferable.

The sparse stage width is F for (AX)W and H for A(XW). Therefore,
matrix dimensions affect the relative arithmetic and memory work.
Earlier experiments with reversed feature dimensions also showed
that the preferred association can change.

A robust final implementation should therefore evaluate association
choice as a function of matrix dimensions rather than assuming that
v17 is always optimal.

Limitations / Next Validation
-----------------------------
The current benchmark has exactly 16 nonzeros per row.

A graph-convolution application can involve irregular or power-law
degree distributions. Such a workload may expose substantially
different:

    - cache behavior
    - sparse-row work distribution
    - OpenMP scheduling behavior
    - load imbalance
    - scalability

An irregular/power-law workload should therefore be tested before
drawing conclusions about parallel scheduling or finalizing the
OpenMP design.
